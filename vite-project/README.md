## Run

Use Node.js 22.12+ (or another version supported by Vite 8).

```sh
npm install
npm run dev
```

Optional configuration in `.env`:

```dotenv
VITE_API_BASE=https://hackathon-backend-d180.onrender.com/api/v1
```

The backend must allow the exact browser origin printed by Vite. On 25 October 2026 the hosted backend rejected `Origin: http://localhost:5173` with HTTP 403 `Origin not allowed` and no `Access-Control-Allow-Origin`. This requires a backend CORS allowlist change; it cannot be fixed by frontend request headers. Allow the intended local and production origins, JSON POST/PUT/PATCH/DELETE/OPTIONS requests, and Authorization/Content-Type headers. See [review notes](docs/REVIEW.md).

## Admin → HR → Employee demo

1. Startup reads `/setup-status`. When initialization is required, the company setup form appears. An authorized operator creates the company and first Admin with a password of at least 12 characters and at most 72 UTF-8 bytes. Setup success leads to sign-in. **Do not run setup against the hosted backend merely to test this project.**
2. Admin signs in using the account created during setup. If the company is already initialized, use its existing Admin account. No default credentials or public registration exist.
3. Admin opens **Organization**, reviews the policy, and creates an active department and designation.
4. Admin opens **Users**, creates an HR login by email, copies the one-time temporary password, and shares it privately.
5. HR signs in with that email/password. The app permits only password change and logout until HR changes the password. HR then signs in again with the new password.
6. For HR's own attendance and leave, Admin opens **Users → Link profile** and supplies the same HR email, code, name, department, designation, joining date and salary. The existing HR login keeps its role. HR can refocus the app or sign in again to retrieve the link.
7. HR opens **Employees**, registers an employee using the created units, and privately shares the returned temporary password. CSV import follows dry run → fix any row errors → import; editing the CSV invalidates the dry run.
8. Employee signs in, changes the temporary password, then signs in again. Their dashboard, attendance, leave, profile and payslips use their own account scope.
9. Employee checks in/out and requests future leave. Smart leave only proposes; the user reviews/edits the form and explicitly confirms. HR enters a comment and approves another person's request.
10. HR inspects the dashboard and AI summary, then generates a draft for a closed month containing eligible historical employees. Admin reviews and finalizes without intervening business changes. Current/future months cannot be finalized; a stale draft must be regenerated by HR.
11. Employee opens **Payslips → PDF**. Admin can inspect **Audit log**. Empty histories remain empty until relevant records exist.

## Checks

```sh
npm run lint
npm run build
npm test
npx playwright install chromium
npm run test:browser
```

Browser tests intercept every backend request and verify endpoint/body fields against the saved generated [OpenAPI contract](docs/openapi.json). They do not mutate the live backend. To use an installed Chrome instead of downloading Chromium, set `CHROME_PATH` to its executable before `npm run test:browser`. Tests start Vite on port 5174 automatically.

## Implementation notes

- Startup checks setup availability and validates any restored session through `/auth/me` before rendering protected pages. Transient outages retain the session and offer retry; 401 clears it; permission-related 403 does not log out the account.
- Credentials are handled by the shared client. The current session is stored as `hcm_token`; only the theme is otherwise persisted. Logout and invalid sessions unmount account screens, clearing in-memory lists and one-time passwords. Cross-tab session changes revalidate. Old in-flight account responses are discarded.
- No automatic mutation retries. Concurrent duplicate actions are blocked and protected forms show a working state.
- Policy display excludes scheduled future versions. Employee edits omit unchanged fields; status changes require a future effective date. Salary is versioned separately in PKR; returned integer-paisa values are formatted by dividing by 100.
- CSV is JSON `{csv,dryRun}`; exports are text and PDF downloads are blobs. `me` is used only for the documented employee profile and leave-balance paths.
- AI failures display their safe fallback message, with normal forms/dashboard still available. No provider key is present in the browser.
- Web attendance records server timestamps; it does not claim to verify cameras or location.
